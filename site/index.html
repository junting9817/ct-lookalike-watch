Certificate transparency · Korean banks, couriers and telecoms

Almost nobody bothers to misspell a bank.

A domain built to be mistaken for your bank needs a certificate before it can show a padlock — and every certificate issued anywhere is published within minutes. So I generated every single-character lookalike of fourteen Korean brands I could construct, and asked the public logs which ones exist.

5

of 1,196 possible single-character lookalikes have ever held a certificate. That is 0.42%, and it is a complete answer over that space rather than a sample: every one of them was asked about.

What none of this says

That any of them is a phishing site. A certificate proves somebody asked for a name and could show control of it — nothing more. Each could be a brand's own defensive registration, a researcher, or a squatter waiting to sell. Nothing here was resolved, fetched or visited, deliberately: a lookalike is usually hosted on somebody else's compromised machine, and a DNS lookup tells the operator that someone is watching.

The awkward half

The hyphen class is mostly the banks protecting themselves

19 of 504 hyphenated names exist — nine times the rate of the homoglyphs. Almost none of it is an attack: woori-bank.com, shinhan-card.com and kb-star.com are what a trademark lawyer tells a bank to register.

This is where scoring stops being able to help. A brand that lets a defensive registration lapse and renews it later looks identical to a squatter picking one up, and certificate transparency does not record who owns a domain. So the tool ranks shapes and a person settles ownership, with the verdict written down so the same name is never judged twice.

Method

Generate the names, then ask whether they exist

The obvious approach — search the logs for each brand name — does not work: that query is an unindexed scan, and the index answers it with a timeout, an error, or success and an empty result, which is indistinguishable from "nothing matched". Exact-name lookups are reliable, so the question was turned around.

That inversion has a cost, stated plainly: this finds only the impersonations it thought to generate. A lookalike built some other way is invisible to it.

The canary

Because the index can return an empty success, every batch first asks about names that certainly have certificates. If none can be confirmed, the run stops rather than recording hundreds of names as "no certificate found" — every one of them wrong, and all of them looking like a clean night's work. It fired for real on the first scheduled night, against a domain holding 4,114 certificates.

Limits

What this cannot tell you

  • Only what was imagined. One substitution at a time, from a curated table of confusable characters, across a short list of likely suffixes. Two substitutions, an unusual character, or a name that impersonates by structure rather than spelling — all invisible.
  • Fourteen brands. Korea's other banks, couriers and retailers are outside every number here.
  • Existence is not intent. A certificate can be issued and never used. Absence is worse: it was true on the day it was asked and decays immediately.
  • No attribution. No WHOIS, no DNS, no page fetched. Who registered these names is a question this project is built not to answer.

1,789 of 6,401 generated names asked about between 2026-09-17 and 2026-09-28; 35 exist. Built on a single small cloud VM alongside a network monitor, a honeypot and an endpoint detection project. Source of truth is the public Certificate Transparency index; nothing else was contacted.
